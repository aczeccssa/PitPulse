# V1 本地端到端验收

验收日期：2026-10-09。fixture → Provider → SQLite → REST 的本地闭环和历史 Provider 读取已实测。本文件按时间记录证据；早先将普通窗口枚举失败归为 App Popup 未验收的判断已由文末真实 MenuBarExtra 联调补记更正。

## 可复跑 fixture 服务

`server/examples/v1_acceptance.rs` 复用已有 Jolpica Alpha／Ergast fixture、Provider、`CalendarSync`、`ResultsSync` 与生产 REST router。从空 DB 同步 2026 Australia fixture、Race 成绩、WDC/WCC，并为积分 UI 场景补入 2025 赛季 fixture；再绑定两个 loopback 端口：API 和只供本地验收控制的 `CONTROL`。传入 DB 路径可跨进程重启；完整 fixture 已存在时不重新 seed，保留被更正的业务 revision。

运行时会打印 API、CONTROL 地址和 fixture 是首次同步还是复用持久快照。不要将本地验收服务暴露到局域网或公网。

```sh
DB_DIR="$(mktemp -d)"
DB_PATH="$DB_DIR/pitpulse.sqlite"
cargo run --locked --manifest-path server/Cargo.toml --example v1_acceptance -- "$DB_PATH" 38701 38702
```

MenuBar UI test 固定使用 API `127.0.0.1:38701` 和 CONTROL `127.0.0.1:38702`；若端口已占用，先停止占用它们的验收进程。

保持该进程运行，在另一终端执行真实状态栏 UI 验收：

```sh
xcodebuild -quiet -project macos/F1Companion.xcodeproj -scheme F1CompanionUITests -destination 'platform=macOS,arch=arm64' CODE_SIGNING_ALLOWED=NO test
```

UI test 通过 `app.statusItems` 打开 MenuBarExtra，再从 Popup 的 AX dialog 操作成绩、积分和赛季选择器；它不使用普通主窗口查询。若 XCTest 报告 status item 坐标落在屏幕外，检查活动显示器布局后再重跑；这属于输入坐标前置条件，不表示 fixture 或页面断言失败。

使用输出的端口读取 REST（当前路径示例）：

```sh
curl "$API/api/v1/health"
curl "$API/api/v1/calendar?season=2026"
curl "$API/api/v1/sessions/2026:1:race/results"
curl "$API/api/v1/standings/drivers?season=2026"
curl "$API/api/v1/standings/constructors?season=2026"
```

把启动输出的 `API=http://127.0.0.1:...` 和 `CONTROL=http://127.0.0.1:...` 分别设为同名 shell 环境变量。真实 App 的 Preferences 中把服务器地址设为输出的 `API` loopback 地址，不填 Token；本 harness 的 REST API 和控制接口都只绑定 `127.0.0.1`。控制接口没有鉴权，只能用于可信本机 fixture。

### 结果更正与限流

```sh
curl -X POST "$CONTROL/revision/2"
curl -X POST "$CONTROL/sync"
curl "$API/api/v1/sessions/2026:1:race/results"
curl -X POST "$CONTROL/rate-limit/true"
curl -i -X POST "$CONTROL/sync"
curl "$API/api/v1/sessions/2026:1:race/results"
curl -X POST "$CONTROL/rate-limit/false"
```

结果 fixture revision 2 将首行积分改为 26，因此内容变化会提升 REST business revision；限流控制让 fixture Provider 对读取返回 HTTP 429 和 `Retry-After: 2`。本地同步控制会报告失败，已缓存成绩仍可读。真实错误 Token 未在此 harness 演练：生产 router 的 bearer 拒绝由 `server/tests/api.rs::test_bearer_token_is_enforced_when_enabled` 覆盖，AppModel 收到 401 后等待凭据变化由 XCTest 覆盖；harness 有意关闭 token，避免把测试凭据写入用户 Keychain。

### 停服、备份与恢复

用 `Ctrl-C` 正常停止进程。SQLite CLI 的 `.backup` 可在线创建一致备份，再以备份副本路径重启 harness；已存在的完整快照会被复用，不会被 fixture 初始版本覆盖。本轮在原服务仍运行时备份，随后停服并以备份副本重启。

```sh
sqlite3 "$DB_PATH" ".backup '$DB_DIR/pitpulse-backup.sqlite'"
RESTORED_DB="$DB_DIR/pitpulse-restored.sqlite"
cp "$DB_DIR/pitpulse-backup.sqlite" "$RESTORED_DB"
cargo run --locked --manifest-path server/Cargo.toml --example v1_acceptance -- "$RESTORED_DB"
```

## 本轮实测记录

- 初始空 DB fixture 同步后，健康、赛历、Session Race、WDC、WCC REST 均返回 200；各页面分别有 1 个 fixture 项。赛历／成绩／积分来自现有 adapter 与同步服务，不是生产数据库。
- 控制 revision 2 后，Race REST 从 revision 1 更新到 revision 2，首行积分为 26。随后上游 fixture 429，控制同步失败而已存 REST 成绩保持可读。
- SQLite `.backup` 后停止服务，以备份副本重启；REST 仍返回一行、revision 2、积分 26，证明 restore 路径未被启动 seed 覆盖。
- 真实历史读取：2026-10-09T09:36:01Z 读取 [Jolpica Alpha 2026 赛历](https://api.jolpi.ca/f1/alpha/schedules/2026/) 和 [阿塞拜疆站 Race](https://api.jolpi.ca/f1/alpha/results/round_St4SXfGd/R/)，HTTP 200；赛季 24 events，Race 22 results，来源 `jolpica-alpha`。Provider 不返回质量字段；按当前 PitPulse Alpha 完整性规则记录为 `provisional`，不宣称 final。
- 本机 Developer ID Application 签名构建及 `codesign --verify` 通过；Computer Use 启动隔离 MenuBarExtra App 仍超时。隔离进程启动后未进入可访问应用列表，也没有可操作 AX 窗口，故未能证明 App 实际连接以上 REST，也未保存运行界面截图／VoiceOver 证据。T08-A1 仍是 T11 本地 UI 验收的前置缺口；错误 token、真机断网、睡眠唤醒和公开服务访问均未伪装为通过。

至少一次真实练习赛结束后由生产调度器自动获取，继续保持 pending。上述历史单次读取与 fixture 不替代真实赛后时效观测；需在实际赛期记录 Session 结束时刻、首次可读时刻及后续修订。
